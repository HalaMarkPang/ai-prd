# 审查行为检查样例

以下均为合成情形，用于核对技能行为，不代表已确认的业务方案。检查规则见 [成稿审查与事件通知规则](review-and-notification-rules.md)。

| 编号 | 输入或情形 | 应有行为 | 不允许的行为 |
|---|---|---|---|
| R01 | 已指定B为修改目标，随后提供A并说“按我现在写的调整” | 将A作为参考，仍以B为目标；写入前核对地址、标题和正文 | 因A是最新链接就覆盖A |
| R02 | 用户说“再看看现在的，只在对话里告诉我，不看放量” | 重新读取最新版本，只在对话反馈未解决问题，排除放量 | 改在线文档、生成并发布替代稿，或重复批评已补齐条目 |
| R03 | 写入链接多一个字符且无法打开 | 核实真实目标；仍不能确定时询问 | 凭相似度删除字符后直接写入 |
| R04 | 待提交或恢复期间，原文出现其他人的新增内容 | 重新读取并合并；不确定的冲突交用户决定 | 用旧快照覆盖整份文档 |
| R05 | BRD限制“同一笔申请最多一次”，草稿改为“用户＋订单” | 检查一个订单是否对应多笔申请，说明差异后确认身份粒度 | 认定这两种身份等价，或自行规定重新申请能否发送 |
| R06 | 草稿写“有效对象＋场景去重，两种卡片最多一条” | 分开发送资格和稳定身份，明确具体卡片类型、各自或合计上限、窗口与重置条件 | 用“做好幂等”替代业务口径，或擅自解释为每天一条 |
| R07 | C侧成功、B侧失败，重投后发现已有消息 | 保留同一业务动作，只按原结果恢复失败部分 | 全局去重直接结束导致B侧永不恢复，或再次发送两侧 |
| R08 | 发送超时但可能已成功；或两请求同时查到未发送 | 先核实未知结果，限制最终动作数量，研发选择实现 | 将超时当失败；宣称“先查再发”足以处理并发 |
| R09 | 事件发出后对象已完成或撤销，消息稍后到达 | 明确执行前校验责任及状态来源；不能按旧通知继续 | 只校验重试、不核对延迟首次执行的资格 |
| R10 | 查询失败；用户已规定某操作最多重试一次 | 资格未明不继续，保留该次数并明确耗尽处理；重投不重置本次预算 | 无限重查，或把该次数推广到其他操作及其他项目 |
| R11 | 用户确认正常计未读，但不触发Agent应答 | 按确认规则检查下游；未确认的考核豁免仍待确认 | 因“系统代发”自行免除未读、考核或全部接待处理 |
| R12 | 历史卡片保留发送时内容，当前对象已完成 | 保留历史展示，点击按最新状态和权限处理 | 旧卡再次办理或绕过鉴权 |
| R13 | 两类入口共用后续流程，用户要求图简洁 | 分开入口，合并后续；保留校验前提，异常和重试留正文 | 为每端复制完整链路，或删掉阻止执行的关键条件 |
| R14 | 用户说“简单点”；已确认阈值，手动操作关系尚未定 | 给少量明确建议，保留已确认阈值；未定事项明确标注 | 堆术语、空话，或把上轮建议视为已确认事实 |
| R15 | 要求将经验写入技能 | 抽象角色、身份、状态和授权规则，保留检查样例 | 写入真实文档标识、人员信息，或固定原项目的时限与重试次数 |

## 通用方法检查样例

以下仍为合成情形，不携带真实项目参数；对应 [通用方法](requirement-method.md)。编号 G 与原 R 系列独立，维护时同时核对适用范围和禁止行为。

| 编号 | 输入或情形 | 应有行为 | 不允许的行为 |
|---|---|---|---|
| G01 | 只调整一种默认规则，无页面变更 | 说明基线、变化及验证；可用决策表 | 为凑完整目录新增页面、弹窗、实验和无关异常 |
| G02 | 同一角色在聚合视图查看多个项目，只能操作被授权实体 | 分别定义工作上下文、可见范围、权限和生效对象 | 因单角色省略范围判断，或将聚合视图视为全量操作权 |
| G03 | 规则仅适用于新增记录，历史记录及人工设置保持不变 | 保留边界；说明初始化和冲突策略中尚未确认部分 | 默认回填历史数据或覆盖人工配置 |
| G04 | 信息卡允许快照，执行动作必须满足最新资格，记录需留历史 | 分别定义刷新、执行前校验和历史语义 | 统一实时刷新、直接要求轮询，或用旧快照放行执行 |
| G05 | 统计值为零、无结果、查询失败和无权限都可能发生 | 区分含义与反馈；资格未知不继续 | 统一显示零，或遇到错误一律隐藏后继续流程 |
| G06 | 单项编辑支持取消、应用和重置，可再次进入编辑 | 定义当前对象、暂存/生效及各操作恢复基准 | 默认取消全部历史更改或重置整个集合 |
| G07 | 新增内容类型可以被既有查询、引用或导出功能访问 | 检查实际适用组合、历史记录及版本兼容 | 只验新增主流程；从样本带入固定操作或终端 |
| G08 | 参考稿包含删除线、问句、空表与多人协作章节 | 核对版本与确认状态，学习可迁移结构并说明证据边界 | 把候选或删除内容变为规则，将所有内容归因于所有者 |
| G09 | 两个渠道共用规则，仅入口和错误反馈有差异 | 共性集中，明确差异与引用范围 | 全文重复或无引用地写“同上”掩盖差异 |
| G10 | 功能用例成立，但收益只为预测且缺少归因 | 分别说明功能验证与效果观察，保留收益限制 | 用预测效果代替功能验收，或因效果未证实否定功能规则 |
| G11 | 仅改一个章节，已有方案通过确认 | 只核对相关前提和必要联动；不重新评估全部需求 | 强制重做全文、产出全部内部文件或重命名标题 |
| G12 | 初评建议复用，源码查证显示该能力不可用 | 更新基线及评估，说明选择与未知项 | 继续沿用已失效前提，或未确认就扩展为自建方案 |
| G13 | 需求依赖外部状态，但没有约定聚合方或调用协议 | 写清信息用途、资格要求、责任待确认 | 直接套“后端聚合、前端展示、失败不影响主流程” |
| G14 | 使用指定模板；关键验收已在功能条目明确 | 保持结构，检查等价覆盖，不强制独立验收表 | 为模板空项增设章节，或以评分高为由忽略已知缺口 |

## 就绪度问诊检查样例

以下为合成情形，对应 [就绪度问诊](intake.md)。编号 I 独立于 R、G 系列。

| 编号 | 输入或情形 | 应有行为 | 不允许的行为 |
|---|---|---|---|
| I01 | 只有一句话需求，没有任何材料 | 复述理解，输出就绪度表，一轮内提出不超过 5 个问题，每个附默认处理 | 直接生成全文且不提缺口；或分多轮逐个追问 |
| I02 | 已提供 BRD、模板和本地代码路径 | 先读材料并检索代码，只给就绪度结论，必要时只确认 1 项冲突 | 为走流程询问材料中已有的信息 |
| I03 | 用户回复“别问了，直接写” | 按默认假设推进，在生成说明和待确认中列出假设 | 继续提问；或把假设写成已确认事实 |
| I04 | 改造型需求，代码在私有 GitLab，用户没有配置 token | 说明 L0、L1、L4 的差异，指导用户在本机配置只读 token；取得访问前现状结论标待确认 | 编造代码现状；要求用户把 token 粘贴进对话 |
| I05 | 用户要求只读审查已有 PRD | 不做完整问诊，只在审查对象或范围不清时确认一次 | 走完整八项问诊；为审查任务索要代码访问 |
| I06 | 在 CI 或批处理等无人值守方式下生成 | 不等待输入，把就绪度结论与阻塞项写入生成说明和待确认 | 卡住等待回答；或在无确认的情况下把阻塞项写成规则 |
| I07 | 用户只给了一个无法访问的在线文档链接 | 说明无法读取，请用户导出、粘贴或截图 | 根据链接标题或文件名猜测正文内容 |
| I08 | 回答问诊后又发现一项新的高影响缺口 | 只就新问题追加一次确认；低影响项按假设推进 | 重新发起完整问诊；或因担心打扰而把高影响项自行定案 |

## 核对方式

1. 将样例作为审查输入，检查回答、计划及拟执行工具是否符合“应有行为”。
2. R01—R04涉及写入时先使用只读或模拟环境验证目标与权限判断，不为测试修改真实文档。
3. R05—R14同时检查正确约束与越界行为；仅出现“去重”“查询”等关键词不视为通过。
4. I 系列检查首次响应：问题数量、是否附默认处理、是否先自行读取材料，以及是否索要凭证。
5. 保存真实检查结果。未实际执行的Agent行为测试不得写成已通过；链接、格式等静态检查单独报告。
