# 材料来源与读取

本文件说明如何读取不同来源的需求材料，以及读取后怎样核对完整性。目标是基于完整材料工作，不以标题、摘要或链接文字猜测内容。

## 1. 读取优先级

| 来源 | 读取方式 | 注意事项 |
|---|---|---|
| 对话中粘贴的文本 | 直接使用 | 记为“用户明确说明”或“原始材料”，注意区分 |
| 本地 Markdown / TXT / HTML | 直接读取文件 | 保留标题层级与表格 |
| 本地 Word / PDF / Excel / PPT | 用客户端的文件读取能力或文档转换工具 | 检查表格、批注、页眉页脚和嵌入图片是否丢失 |
| 截图、原型图、流程图 | 用视觉能力识别 | 转成页面信息，不只写“见截图” |
| 在线文档链接 | 优先使用客户端已接入、且用户有权限的连接器、命令行工具或浏览器 | 无法读取时请用户导出或粘贴 |
| 会议纪要、邮件、聊天记录 | 用户提供的文本或导出文件 | 区分已确认结论与讨论过程 |

## 2. 在线文档

常见来源包括 Notion、Confluence、Google Docs、飞书 / Lark、语雀、钉钉文档、腾讯文档以及各公司内部的 Wiki 或文档平台。

1. 先检查当前客户端是否有可用的连接器、MCP 服务、命令行工具或浏览器，并且用户已经登录、有权读取该文档。
2. 读取正文时保留标题层级、表格、图片说明和批注。读取结果过短、表格丢失或图片缺失时，换一种方式读取，或请用户提供导出文件。
3. 无法读取时直接说明，并请用户选择：导出为 Markdown、PDF 或 Word；复制正文粘贴；或提供截图。不得只凭链接标题推断内容。
4. 记录文档标题、读取时间和版本信息（如有），便于后续核对是否为最新版本。
5. 读取在线文档不等于获得写入授权。写回在线文档需要用户明确要求，并遵守 [成稿审查规则](review-and-notification-rules.md#1-先确定读什么改哪里)。

## 3. 截图与原型

截图必须转成页面信息，至少提取：页面名称、区域、控件和字段、用户可执行的操作、状态变化、空态、加载态、错误态，以及与前后页面的关系。

- 截图带批注（箭头、圈选、文字标注、编号）时，识别批注意图，把对应改动落成明确需求。
- 识别浮层形态：弹窗、气泡、抽屉、半屏浮层、Toast。写清触发方式、承载内容、关闭方式、是否阻断主流程、是否影响底层页面状态。
- 超出图像可确认范围的交互和行为，标为待确认，不从静态截图推断。

## 4. 模板与样稿

1. 用户提供了自己的模板或样稿时，它是格式上优先级最高的材料。先学习标题写法、章节层级、表格字段、链路描述、功能颗粒度、待确认问题写法和代码线索的保留程度。
2. 用户模板的一级结构与本技能的 PRD 模板不同时，把范围、现有链路、外部依赖、验收、跨团队依赖、待确认问题和代码线索等内容归入用户模板的对应章节，不额外新增一级章节。
3. 用户没有模板时，参考 [PRD 模板](../templates/prd-template.md) 并按复杂度裁剪。

## 5. 完整性与版本核对

读取后、建模前完成以下检查：

- [ ] 正文、表格和必要图片都已读取；未能读取的部分已向用户说明。
- [ ] 区分当前有效内容、历史删改、候选方案、待确认内容与模板残留。删除线不恢复为规则，问句和占位示例不视为已完成的设计。
- [ ] 多份材料或多个版本冲突时，按明确的确认记录处理；没有依据时列出冲突与影响，交由用户裁定。
- [ ] 多人协作文档不按文档所有者推定全部内容的作者。

## 6. 隐私与安全

- 不要求用户在对话中粘贴 token、密码或 cookie。需要授权时，指导用户在本机配置。
- 用户材料中出现个人信息、客户数据或内部系统凭证时，不复制进 PRD 正文；必要时提醒用户脱敏。
- 不把用户的私有文档或代码上传到未经用户同意的第三方服务。
