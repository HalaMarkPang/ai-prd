# AI-PRD

AI-PRD 是用于生成、修订与审查产品需求文档（PRD）的 Agent Skill。它规定从需求材料到研发可评审稿的工作流程、判断规则与验证标准，适用于 Claude Code、Codex、Cursor 等支持 Skill 或规则文件的 Agent 客户端。

## 解决的问题

由模型直接生成的 PRD，常见缺陷包括：

1. 材料未读完或信息不足时仍产出全文，关键结论建立在推测之上。
2. 未判断需求是否成立，即将体验抱怨、原因猜测与建设目标混同，并进入方案设计。
3. 对现有系统的描述缺乏可核对依据，与实现不符。
4. 套用固定模板，与团队既有格式和评审要求不一致。
5. 用户仅要求审查或局部修改时，仍改写全文或写入在线文档。

## 工作机制

| 问题 | 机制 | 规则文件 |
|---|---|---|
| 信息不足或未通读即生成 | 材料通读闸门与就绪度问诊：指定材料须完成通读（或声明部分读取边界）后方可给出完整结论；八项检查标注为“已具备 / 可假设 / 阻塞”，开场就阻塞项集中提问至多 5 个，每项附默认处理 | [requirement-method.md](references/requirement-method.md)、[intake.md](references/intake.md) |
| 未判断需求是否成立 | 需求评估前置：陈述分层（事实 / 解释 / 价值判断 / 目标）；从真实性、必要性、替代方案、范围给出结论；多方案须先对峙；影响建设与否的关键未知先澄清，不以待确认清单替代澄清 | [requirement-method.md](references/requirement-method.md)、[prd-generation.md](references/prd-generation.md) |
| 现状描述缺乏依据 | 代码访问分级（L0–L4）与取证纪律：现状结论须回读至 `文件:行号`；涉及既有改造时按实际链路逐跳核对；无法核对的列入待确认 | [code-evidence.md](references/code-evidence.md) |
| 格式与团队要求不符 | 格式优先级：用户模板或样稿优先；未提供时使用本技能 PRD 模板，并按复杂度裁剪。默认模板含验收与代码线索；用户要求外置时从其约定 | [prd-template.md](templates/prd-template.md) |
| 越权修改 | 任务模式与读写授权：完整生成、评审精简稿、局部修订、只读审查；未经用户明确要求，只读任务不转为写入 | [prd-generation.md](references/prd-generation.md#执行模式)、[review-and-notification-rules.md](references/review-and-notification-rules.md) |

## 工作流程

```text
确定任务模式与读写授权
→ 通读指定材料（或声明部分读取边界）→ 就绪度问诊
→ 需求评估（陈述分层；关键未知先澄清；多方案先对峙）/ 变更影响核对（局部修订）
→ 按需查证现状
→ 建立变更基线与业务模型
→ 定义规则、数据、交互与依赖
→ 按用户格式生成正文或修订片段
→ 审查与验证，在授权范围内交付
```

## 约束与边界

1. **通读**：完整评估结论与完整正文定论须在指定材料通读完成后给出。章节导航与材料包摘要仅用于定位原文。仅完成部分读取时，只给出限定于已读范围的阶段判断，并说明未读影响。
2. **问诊与澄清**：开场就绪度问诊集中一轮、至多 5 个问题，每项注明原因与默认处理；材料齐全时不提问。进入评估后，仅当未知仍可能改变建设与否、范围或方案时一次一问。澄清问题在交付前处理；待确认章节仅保留交付时仍未决项。
3. **只读审查**：反馈结论后结束，不生成文件，不写入任何文档。用户随后明确要求修改时，转为局部修订，并在写入前确认写入目标。
4. **修订上限**：内部审查评分低于 85 分时，至多修订两轮。仍未达标时停止自行修订，列出未达标维度与缺口，由用户决定补充材料、接受当前版本或转由人工处理。
5. **非交互运行**：在 CI 等无人值守环境中不提问、不中止任务；阻塞项与所采用假设写入 PRD 开头的“生成说明”和“待确认问题”，并注明未经用户确认。

## 安装

以 `SKILL.md` 为入口，并引用 `references/` 与 `templates/` 下的规则文件；安装时须保留完整目录。

| 客户端 | 安装方式 |
|---|---|
| Claude Code | `git clone https://github.com/HalaMarkPang/ai-prd ~/.claude/skills/ai-prd` |
| Cursor | 克隆至 `~/.cursor/skills/ai-prd`，或项目内的 `.cursor/skills/ai-prd` |
| Codex | 克隆至 `~/.codex/skills/ai-prd`，或在 `AGENTS.md` 中引用 `SKILL.md`，并确保整个目录可读取 |
| 其他 Agent | 指示 Agent 读取 `SKILL.md` 及其引用的全部文件；仅提供 `SKILL.md` 无法加载完整规则 |

方法同步边界见 [SYNC.md](SYNC.md)。

## 使用

在对话中说明任务目标并提供相关材料。下列示例对应四种任务模式：

| 任务模式 | 示例 |
|---|---|
| 完整生成 | 使用 AI-PRD，为“任务逾期提醒”生成 PRD；代码位于 `~/code/my-product`。 |
| 评审精简稿 | 基于本 BRD 生成研发评审稿，按附件中的团队模板组织。 |
| 局部修订 | 仅修订本 PRD 的“异常与失败处理”一节，其余内容保持不变。 |
| 只读审查 | 审查本 PRD，仅在对话中反馈问题，不修改文档。 |

Agent 的首次回复包含需求理解、就绪度表，以及须确认的问题（若有）。用户可逐项答复，或指示按默认假设继续；选择后者时，所采用假设写入 PRD 开头的“生成说明”和“待确认问题”。

完整过程见示例 [任务逾期提醒](examples/overdue-task-reminder/README.md)。示例中的产品、数据与代码均为虚构。

### 代码访问

涉及已有系统改造时，Agent 在问诊中确认代码访问方式，并在 PRD 中注明实际采用的级别：

| 级别 | 条件 | 现状结论的依据 |
|---|---|---|
| L0 | 不提供代码 | 无；相关结论全部标为待确认 |
| L1 | 提供代码片段或接口文档 | 仅限所提供的内容 |
| L2 | 仓库位于本机 | 本地只读检索，核对至 `文件:行号` |
| L3 | 跨仓库，调用链复杂 | 图谱或引用关系定位后回读源码 |
| L4 | 仓库位于 GitHub、GitLab 等远端 | 平台只读接口；召回范围通常窄于本地检索 |

公开仓库无需凭证。私有仓库的访问凭证仅保存在用户本机环境变量中；Agent 不在对话、PRD 或日志中记录凭证。

## 输出约定

- PRD 正文面向研发评审。就绪度问诊结论、需求评估、输入事实与约束、需求模型、审查报告和评分属于内部过程产物，默认不写入正文。
- 关键结论标注来源：用户明确说明、原始材料、已有 PRD、代码或系统现状、合理推断、待确认。
- PRD 描述产品侧的数据需求、业务含义与异常处理要求；不定义接口字段名、错误码、超时、缓存等技术参数，除非来自已确认的接口文档。
- 指标的口径、数据源、时间窗或归因方式不完整时，仅作为上线后的观察指标，不写为目标承诺。
- 功能正确性、运行质量与业务效果分别验证；未执行的测试不标记为通过。
- 静态原型仅支撑图中可见的布局与操作；可点击原型作为独立验证附件时，不替代 PRD 正文结构。
